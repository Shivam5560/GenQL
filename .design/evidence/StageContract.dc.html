Stage event — data contract

The pipeline knows far more than it says.

Every node hands the graph a rich delta — typed entities with scores, defects, violations, rationales. to_stage_event() flattens all of it to one string of at most 200 characters, and the browser then throws away any string that looks like a dict. Four of the twelve stages emit nothing at all.

Fix the envelope first — it applies to all twelve
Today
stage: str status: completed | paused | failed detail: str | None  # truncated to 200
Add
status += skipped  # with skip_reason started_at: datetime duration_ms: int attempt: int  # retry / repair round
facts: dict[str, str | int | float] model: str | None prompt_version: str | None tokens_in / tokens_out / cost_usd

Why skipped matters most. A stage that never reported is currently indistinguishable from one that ran silently — which is why the live rail sorts Intent, Domain scoping and Schema linking to the bottom of the list, greyed out and numbered 11–13, after stages that ran later. The rail is not wrong; it has nothing to go on. One extra status value fixes the ordering bug and the honesty problem at once.

The shape of the change

Keep detail as the one human line — the CLI and the live stream both want it. Add facts beside it as a flat dict, and one optional typed payload per stage. Nothing already shipped has to change its reading, and a stage with no entry still streams, which is the same open/closed property the summariser lookup has today.

The cap is the wrong instrument

200 characters exists to keep the transport narrow, and it is right to keep the stream narrow. But the trail is now persisted with the turn and read back weeks later, so the store and the stream want different budgets: stream the line, persist the payload, and let the rail fetch a stage's detail when someone opens it.

What it buys in review

Reproducibility (model, prompt version, cost per turn), auditability (which guardrail caught what, on which candidate), and regression evidence (per-stage latency and confidence, comparable across a golden set). Those three are what separates “it explains itself” from “it prints a progress bar”.
