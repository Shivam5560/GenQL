Waiting states

One spinner, three placements, one rule.

The rule: a control that started work keeps its own progress. Never move the feedback somewhere else on the screen, never swap a button’s label without also holding its width, and never show a spinner for something that has not started.

The primitive

A 270° arc on a 30% track, 0.7s linear, currentColor so it inherits from whatever it sits in — muted in a ghost button, white on brand, brand on the empty ground. It is the only motion in the set; everything else here is a pulsing surface, which reads as “content is coming” rather than “something is spinning”.

Honour prefers-reduced-motion: swap rotation for the breathing opacity used by the skeletons.

1 · Sign in

The submit button already swaps its label. Add the spinner, freeze the width, and disable the fields — a form that still accepts typing while it is posting invites a second submit.

The OAuth buttons navigate away, so they need one too — otherwise the gap between click and redirect reads as a dead button.

2 · Sign out

The confirm dialog’s primary button holds the progress. The sidebar row behind it dims but does not change — there is nothing useful to say there.

Sign-out must not hang on a failed network call. If /logout errors, clear the local session anyway and say so on the login screen — a user who asked to leave should always leave.

3 · Session boot

Today this is the bare word “Loading…” centred on an empty page while the refresh token round-trips. Draw the shell instead — it is a known layout, so there is no reason to show nothing.

Restoring session

Hold it for 250ms before painting. A warm refresh usually resolves faster than that, and a flash of skeleton is worse than no skeleton.

Not a toast

Progress for something the user just clicked belongs on the thing they clicked. The corner of the screen is for events they did not cause — an ingestion finishing minutes later.

Not a full-screen overlay

Signing in and signing out are sub-second. Blanking the page for them makes a fast action feel slow and steals the reader’s place.

Not a jumping button

“Enter AuraSQL” and “Signing in” are different widths. Set min-width from the idle label so the control holds still while it works.
